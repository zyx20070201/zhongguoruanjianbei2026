# Synapse Link 星火 X2 云服务器部署改动说明

## 1. 改动目的

将 Synapse Link 的文本大模型服务统一切换为讯飞星火 X2。

- 接口协议：OpenAI 兼容的 Chat Completions
- API 基础地址：`https://spark-api-open.xf-yun.com/x2`
- 完整请求地址：`https://spark-api-open.xf-yun.com/x2/chat/completions`
- 模型名称：`spark-x`
- 鉴权方式：`Authorization: Bearer <APIpassword>`

项目继续复用现有 OpenAI 兼容适配器，因此运行记录中的 Provider 可能显示为 `openai`，但实际请求地址和模型分别为星火 X2 与 `spark-x`。

## 2. 需要同步的代码文件

必须同步：

```text
backend/src/config/loadEnv.ts
```

建议一并同步：

```text
.gitignore
backend/.env.example
```

本次改动不涉及前端、数据库结构、Prisma Migration、Qdrant、Judge0 或现有课程数据。

## 3. 创建服务器本地配置

进入项目后端目录：

```bash
cd /path/to/Synapse-Link/backend
```

创建 `backend/.env.local`。该文件仅保存在服务器，不提交 Git：

```env
AI_DEFAULT_PROVIDER=openai
AI_CHAT_PROVIDER=openai
AI_STUDIO_PROVIDER=openai
AI_STUDIO_FALLBACK_PROVIDERS=openai
AI_PLANNER_PROVIDER=openai
AI_LEARNING_PROVIDER=openai
AI_TERMINAL_PROVIDER=openai
AI_MEMORY_PROVIDER=openai
AI_FLASHCARD_PROVIDER=openai
AI_QUIZ_PROVIDER=openai
AI_RESOURCE_PROVIDER=openai
AI_VIDEO_PROVIDER=openai
AI_TABLE_PROVIDER=openai

OPENAI_API_KEY=<在此填写星火 X2 APIpassword>
OPENAI_BASE_URL=https://spark-api-open.xf-yun.com/x2
OPENAI_API_MODE=chat_completions
OPENAI_MODEL=spark-x
AI_PLANNER_MODEL=spark-x
AI_TERMINAL_MODEL=spark-x
```

限制配置文件访问权限：

```bash
chmod 600 .env.local
```

注意事项：

- `OPENAI_BASE_URL` 填写到 `/x2` 即可，不要重复添加 `/chat/completions`。
- `OPENAI_API_KEY` 使用星火 HTTP 接口的 APIpassword，或官方支持的 `AK:SK` 格式凭据。
- 后端进程工作目录应为项目的 `backend` 目录，否则程序可能无法找到 `.env.local`。
- 不要把真实密钥写入 `.env.example`、源码、部署日志或聊天截图。

## 4. 安装依赖与类型检查

```bash
cd /path/to/Synapse-Link/backend
npm install
npx tsc --noEmit
```

类型检查无输出且退出码为 `0` 表示通过。

## 5. 重启后端

### 5.1 PM2 部署

先确认进程名称：

```bash
pm2 list
```

在 `backend` 目录重启：

```bash
cd /path/to/Synapse-Link/backend
pm2 restart <后端进程名> --update-env
pm2 logs <后端进程名> --lines 100
```

PM2 配置中建议显式设置：

```js
cwd: "/path/to/Synapse-Link/backend"
```

### 5.2 systemd 部署

确保 service 文件的 `WorkingDirectory` 指向后端目录：

```ini
WorkingDirectory=/path/to/Synapse-Link/backend
```

随后执行：

```bash
sudo systemctl daemon-reload
sudo systemctl restart <后端服务名>
sudo systemctl status <后端服务名>
journalctl -u <后端服务名> -n 100 --no-pager
```

### 5.3 Docker 部署

将本地配置作为容器环境变量加载，例如在 Compose 服务中添加：

```yaml
services:
  backend:
    env_file:
      - ./backend/.env.local
```

重新创建后端容器：

```bash
docker compose up -d --build --force-recreate backend
docker compose logs --tail=100 backend
```

## 6. 部署后验证

### 6.1 基础健康检查

```bash
curl -s http://127.0.0.1:3001/health
```

预期：

```json
{"status":"ok"}
```

### 6.2 模型配置检查

```bash
curl -s http://127.0.0.1:3001/api/ai/models
```

返回结果中应出现：

```json
{
  "provider": "openai",
  "model": "spark-x"
}
```

### 6.3 星火真实调用检查

```bash
curl -s http://127.0.0.1:3001/api/learning/memory/health | jq '.services.llm'
```

预期核心字段：

```json
{
  "ok": true,
  "configured": true,
  "provider": "openai",
  "model": "spark-x"
}
```

该接口还会检查数据库、Embedding 和 Qdrant。即使整体 HTTP 状态为 `207`，也应单独查看 `services.llm.ok` 是否为 `true`。

最后在 Web 页面分别验证：

1. Workspace AI Chat 可以正常回复。
2. Agentic V2 可以完成一次只读任务。
3. Workbench AI 助手可以正常流式输出。
4. AI Studio 可以生成一个小型文本产物。
5. Planning 可以生成或调整一条学习计划。

## 7. 常见问题

### 7.1 `AppIdNoAuthError`

含义：凭据所属应用没有星火 X2 权限。

处理：在讯飞开放平台确认该应用已领取或开通 X2，并确认使用的是该应用对应的 HTTP APIpassword。开通后重新执行真实调用检查。

### 7.2 仍然显示旧模型

依次检查：

```bash
cd /path/to/Synapse-Link/backend
pwd
grep -E 'OPENAI_BASE_URL|OPENAI_MODEL|AI_(DEFAULT|TERMINAL|PLANNER)_PROVIDER' .env.local
```

确认：

- 后端进程工作目录为 `backend`。
- `.env.local` 文件名和路径正确。
- PM2 重启时使用了 `--update-env`。
- Docker 容器已经重新创建，而不只是重启旧容器。

### 7.3 请求地址出现重复路径

错误示例：

```text
https://spark-api-open.xf-yun.com/x2/chat/completions/chat/completions
```

正确配置：

```env
OPENAI_BASE_URL=https://spark-api-open.xf-yun.com/x2
```

### 7.4 接口超时或返回限流

- 检查服务器是否可以访问 `spark-api-open.xf-yun.com`。
- 检查讯飞控制台中的授权量、日调用量、并发限制和余额。
- 确认同一会话等待上一条请求完成后再发送下一条请求。
- 查看后端日志中的 HTTP 状态和星火错误码，不要输出完整鉴权头。

## 8. 回滚方法

回滚前先备份当前本地配置：

```bash
cd /path/to/Synapse-Link/backend
cp .env.local .env.local.spark-x.backup
```

随后恢复原 Provider 配置或暂时移走 `.env.local`：

```bash
mv .env.local .env.local.disabled
```

重启后端后，系统会重新使用原 `backend/.env` 中的 Provider 配置。回滚不涉及数据库和前端资源，无需执行数据迁移。

## 9. 部署完成标准

- 后端基础健康检查通过。
- `/api/ai/models` 返回 `spark-x`。
- `services.llm.ok` 为 `true`。
- Chat 和 Workbench 流式回复正常。
- Agent V2、Planning、AI Studio 至少各完成一次最小调用。
- 日志中不存在鉴权错误、重复路径或持续限流。
- 真实 APIpassword 仅存在于服务器本地配置或部署平台的密钥管理中。
